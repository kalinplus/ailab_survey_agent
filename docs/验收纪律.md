# 验收纪律（Acceptance Discipline）

按需加载的专项文档（根 `AGENTS.md` 指向这里）。教训代价：2026-09-08；背景见 `docs/DeepSeek与MinerU输出质量问题及后续方案.md` §8。

一个批次/方向的**验收通过必须同时满足**两条：

1. 机制测试通过（unit + targeted），且
2. 交付产物通过**文档级通读**：全文读 `output/survey.md`，逐项对照清单——离题论文、重复/回收的 claim、事实与引用的范围匹配（被引证据是否真的这么说）、可读性、泄漏的内部文本。真跑验收还必须在同 run 的产物上跑 `scripts/run_survey_eval.py`（L0 冗余 + L1 NLI + **L3 judge**——唯一真正读文档的层）；L3 自 2026-09-04 起被跳过，这个缺口正是离题论文和流畅的错误事实连续穿过五次批次验收的原因。

硬规则：

- `review_report.json` 里 `topic_relevance` 低于阈值时，验收报告必须显式回应（修复/豁免/降级交付），绝不静默跳过（0.692 曾无人阅读地躺在最新产物里）。
- `citation_validity` 只能报告为「引用结构合法」，绝不能说「引用正确」；白名单成员资格不说明主题匹配。数量不等于可用性（figure 记录 ≠ 可用图片；evidence 行 ≠ 唯一证据——要查 id 唯一性）。
- 指标与生成器共享同一数据链：跨侧一致性只验证了解析，不验证真实性。白名单「多余垃圾」方向在 canonical 审计里没有检测器——在检测器出现前人工检查。
- 机制验收 ≠ 产物验收。只看数字、不通读交付物就签「批次验收通过」，正是本节要防止的失败模式。
