# EviSurvey 系统架构与流程

> 2026-09-21，按当日代码梳理。这是全局总览，细节在专项文档里（§10 有地图）。
> 读者：要接手这个仓库的人。读完你应该能回答三个问题：这系统在干什么、数据怎么流、为什么长成这样。

---

## 0. 这是个什么系统

给它一个学术主题（比如"世界模型综述"），它产出一篇综述：HTML/PDF 交付，每个论断都引用真实论文里的真实证据，每条引用都查过出处，正文还配图表。它的核心卖点是**不编东西**——论文信息全部来自真实的文献 API，LLM 只负责组织和措辞，没有资格发明事实。

核心 LLM 是 DeepSeek Flash（用于生成）和 Intern-S2-Preview（用于核查）；修复环节的动作选择（分类判断）另有 JEV（TypeSafe System One 模型）分流，无 key 时自动退回 Intern-S2；论文元数据只来自 SciVerse API，杜绝 LLM 编造。

本文按系统能真正立住的三个能力来介绍：**检索策略**（素材从哪来、够不够好）→ **引用验证**（写出来的每句话站不站得住、站不住怎么修）→ **质量评估**（最终交付的东西整体算不算合格）。这三块正好对应数据的三个阶段，是一条贯穿全程的质量链。代码的物理位置住在 `harness/`（调度）和 `tools/`（干活）两个目录里，每节开头会标注"这段代码住在哪"。

## 1. 全局：一条质量流水线

```text
User topic "世界模型综述"
     │
     ▼
┌─────────────────────────────────────────────────┐
│ ① 检索策略 —— 素材从哪来                          │
│    定检索方向 → 真实 API 搜论文/解析 → 做卡片收证据  │
│    → 圈定"允许引用"的白名单                        │
└───────────────────┬─────────────────────────────┘
                    │ 白名单 + 证据库 + 图库
                    ▼
          [写作：模板骨架 + 可选 LLM 段落]
          （为验证而写：论断先行，见 §3.1）
                    │ output/survey.md
                    ▼
┌─────────────────────────────────────────────────┐
│ ② 引用验证 —— 每句话站不站得住                     │
│    结构校验 + 逐句语义校验 + 归属检查               │
│    → 站不住就修（修复 Agent）→ 再查                │
│    （查-修循环由一段纯代码的裁判把关，见 §3.4）      │
└───────────────────┬─────────────────────────────┘
                    │ 修好的 survey.md
                    ▼
┌─────────────────────────────────────────────────┐
│ ③ 质量评估 —— 最终算不算合格                       │
│    运行内评分 + 和基线综述对比 + 渲染交付           │
│    → 事后三层评测（冗余 / 引用 / AI 评审）          │
│    → 诚实状态：completed 或 quality_failed         │
└───────────────────┬─────────────────────────────┘
                    ▼
     output/final_report.html / .pdf + 质量报告
```

两个贯穿全局的规矩：

- **文件就是接口**。模块之间不直接传对象：每一步把结果写成文件（`requests/`、`cache/`、`output/`），下一步读文件。任何一步的输入输出都能打开看、能重放、能对账。
- **流程骨架是写死的代码**（`harness/agent_loop.py`），LLM 无权决定"接下来跑哪一步"。它只在各环节内部做有边界的决策（下文展开）。这样每次运行的骨架可复现，出问题能定位到具体步骤。

四个外部服务（均由 `tools/clients/` 封装，真实 API 优先、无生产 mock）：

| 服务 | 干什么 | 要注意的 |
|---|---|---|
| **Intern-S2**（OpenAI 兼容） | 核查/决策类 LLM：修复决策（JEV 关/不可用时兜底）、改写文案生成、评测评审 | 约 2 秒 1 次，代码里自动节流；它默认会先"思考"再回答，小预算下思考会把答案挤没——所以纯生成类任务路由给了 DeepSeek Flash（关思考），Intern 兜底 |
| **JEV / TypeSafe**（System One 分类模型） | 修复 Agent 的动作选择（封闭选项集分类）：逐失败 Choice 选动作 + 同调用 speculative Choice 选候选 id，返回概率分布 + 置信度，无文本解析 | `EVISURVEY_JEV=auto`（默认，有 `TYPESAFE_API_KEY` 即启用）；只分类不生成（rewrite 文本仍归 Intern-S2）；低置信/无匹配候选/API 失败自动回退 Intern-S2 路径；单组一次调用 <1s，无限速 |
| **SciVerse** | 查论文（meta-search）、查论文里的具体内容片段（agentic-search）、读全文 | 两个接口返回的字段名不一样（`results` vs `hits`）；它返回的作者字段是坏的，得用另一个接口补 |
| **MinerU** | 把 PDF 解析成结构化全文 | 默认**关着**（要 `--use-mineru` 手动开），因为解析经常失败；失败就降级用摘要，绝不造假数据 |

## 2. 检索策略：素材从哪来

> 代码：`harness/agents/strategy_agent.py`、`harness/search_strategy_builder.py`、`tools/phases/phase1~3*.py`、`harness/citation_prelock.py`；外部服务 SciVerse / MinerU。

这部分回答三个问题：搜什么、怎么搜、搜到之后圈定什么能用。

### 2.1 搜什么：方向怎么定（策略 Agent）

检索关键词定不好，后面全歪——搜偏了，再严的验证也只能把综述修得又短又空。所以方向这一步值得花力气：

先零成本探测（直接试查）→ 自动聚类（把查到的论文按相似度分堆）→ 让 LLM 给每堆起名字形成检索方向 → 每个方向试搜采样 → 给 LLM 看一张"成绩单"（每个方向查到几篇、互相重合多少、相关度多高、年份分布）→ 它提出修改（换个查询词、调过滤器、加删方向）→ 再试。最多 3 轮，由**纯代码的闸门**验收，不达标就回滚到最好的版本。

这是 v2 的"关节 1"，只在 `--mode full` 时启用（`EVISURVEY_STRATEGY_AGENT=0` 可关）；不开时退到三级兜底：LLM 单发 → 聚类模板 → 纯模板。

### 2.2 怎么搜：真实 API 检索与解析（P1–P3）

- **P1 主题分解**：把大主题拆成若干检索方向。
- **P2 综述分析**：读本地存同题综述语料，提炼分类骨架 + 补充候选方向。
- **P3 检索解析**：逐方向用 SciVerse 查论文（中文关键词先让 LLM 翻译成英文学术查询，因为英文查出来的效果好得多）；可选开 MinerU 把 PDF 解析成结构化全文。

SciVerse 的两个接口分工：`meta-search` 给论文列表（**元数据唯一来源**），`agentic-search` 给能定位到页码的原文片段（后面证据绑定靠它）。

### 2.3 圈定什么能用：备料与白名单（P5 + 预锁）

- **P5 备料五件事**：给每篇论文做卡片（有全文做深卡、只有摘要做浅卡）；收集证据（论文段落 + 专门反查的内容片段，逐条和论文关联）；挖图；挖表；定分类和引用索引。
- **白名单预锁**：动笔**之前**，先从论文池里挑出"允许引用哪些论文"（标准：新近度和影响力各占一半——纯看新会把 DreamerV3 这类经典挤出去，纯看影响力又会全是老论文）。这份名单（`cache/citation_ready_set.json`）之后写作、校验、修复、渲染全都只认它。**引用合法性从源头收敛，不是靠事后清洗**——这是整个系统最重要的一个设计决定。

## 3. 引用验证：每句话站不站得住

> 代码：`tools/write_survey.py`、`tools/verify_citations.py` + `tools/verify/`、`tools/revise_survey.py`、`harness/agents/repair_agent.py`、`harness/goal_gate.py`。

### 3.1 先说写作：为验证而写

初稿（`write_survey.py`）的章节骨架是确定性模板（保证结构稳定、可复现），正文段落可选走 LLM（`EVISURVEY_WRITER_LLM=1`，默认纯模板）。关键在写作的组织方式是为后面的验证服务的：

- LLM 写正文前先规划**论断数据**（每句话说什么、引哪篇、什么性质——贡献/方法/对比/局限），落笔即带引用标记；
- 写作只能引用白名单内的论文，图表只能来自图库/表库；
- 内置防泄漏：harness 内部术语、裸的论文 id 不允许出现在正文里。

### 3.2 查什么：三层校验

`verify_citations.py` 把正文拆成一句句论断，逐句过三道检查：

1. **结构性**：引用的论文 id 在不在白名单、图引用在不在图库里。（形式对不对）
2. **语义（NLI）**：把论断和它引用的证据做自然语言推断——证据原文真的说了这个吗。（内容对不对）
3. **归属**：论断标了"这是论文自己的贡献/方法/局限"，如果引用的原文里其实是别人的工作（比如满篇 "previous work show..."），就算语义对了也拦——**别人的成绩不能算成引用论文的**。（功劳算谁的）

注意 NLI 有真假两个版本：默认是关键词匹配的假模型（跑测试用），真验证必须 `EVISURVEY_REAL_NLI=1`。

### 3.3 站不住怎么修：修复 Agent

查出问题后，默认的修法是保守删除（删掉不合法的句子）。`EVISURVEY_REPAIR_AGENT=1` 开启 v2 的"关节 2"，修得更聪明：

失败按原因分 6 组——引用 id 写错 / 有证据但说法不成立 / 完全没证据 / 说法过强 / 图引用错 / 把别人的工作说成自己的。**选修复动作**（换引用 / 改写说法 / 换证据 / 补证据 / 删——删是最后手段且必须给理由）是个封闭选项集分类，默认走 **JEV**（TypeSafe 分类模型，`EVISURVEY_JEV=auto`：有 key 就用）：每组失败一次调用，每个失败一个选择题，候选 param（换成哪个 id）在同一调用的 speculative 选择题里一起问，答案被约束在代码给的候选集内——不会再出现幻觉 id。改写文案（rewrite 的新句子）是生成任务，仍由 Intern-S2 写；JEV 置信度低于 0.5、候选全不匹配或 API 失败的记录，逐级回退给 Intern-S2 按老办法批量决策，run 不中断。无论谁决策，代码都验证 id 确实在候选集里才执行，**每句改写重新过语义校验才算修好**。

### 3.4 谁说了算：裁判与兜底

查-修循环（最多 2 轮修复）每轮都由 **Goal Gate**（`harness/goal_gate.py`）裁决——**纯代码，LLM 无权判"过"**。按顺序问：

1. 覆盖跌破 70% 了吗？——正文字数和图表引用数以第一轮为基线，跌破（阈值 `EVISURVEY_COVERAGE_MIN`，默认 0.7）**立即停修**。这是关节 3，防的就是"修复变掏空"：把有问题的句子全删了，指标是好了，综述空了。
2. 有归属违规或证据缺口吗？有就再修一轮。
3. 引用错误和不支持的论断都清零了吗？清了就通过 ✅。
4. 修复轮数到顶了吗？到顶停。
5. 这轮比上轮有进步吗？没进步说明修不动了（fixpoint），停。
6. 否则再修一轮。

**兜底回滚**：每一轮都记住"到目前为止最好的版本"（排法：问题少优先，问题一样多时字多的赢——防止靠删句子刷指标）。修到后面反而变差，就把最好的那版换回来交付。最终报告里的数字描述**实际交付的那版**。

## 4. 质量评估：最终算不算合格

> 代码：`tools/render_report.py`、`tools/evaluate_survey.py`、`scripts/run_survey_eval.py`、`main.py`（退出码）。

### 4.1 运行内评分（自动跑，随报告交付）

`render_report.py` 渲染 HTML/PDF 的同时算 `evaluation_report.json`（总分 + 引用合法性 + 证据支撑度 + 可视化）和 `review_report.json`（含 **topic_relevance 主题相关度**——低于 0.7 的必须在验收时显式回应，不许装没看见），并和 `docs/` 里的基线综述对比。运行内评分如果不达标，应该能够指导相应的生成返修。

### 4.2 事后三层评测（验收用，单独跑）

`scripts/run_survey_eval.py` 对着同一次运行的产物做三层检查：

- **L0 冗余**：正文有没有翻来覆去说同一句话；
- **L1 NLI**：抽样复核引用质量（注意要用真 NLI 模型）；
- **L3 judge**：让 Intern-S2 当评审通读全文打分——**这是唯一真正读文档的评测层**。历史上跳过它，正是跑题论文和"流畅的错话"连过五次验收的原因。

### 4.3 诚实状态

裁判没过不终止运行——报告照常渲染出来给你看，但 `final_state.json` 的状态和进程退出码老实标记 `quality_failed`（非 0）。好就是好，不好不装好。

### 4.4 验收纪律（人的责任）

机制测试绿 ≠ 交付物合格。批次验收必须：通读 `output/survey.md` 全文对照清单（跑题论文？重复论断？引用的证据真说了这个吗？内部术语泄漏？）+ 跑一遍三层评测。规则全文见 `docs/验收纪律.md`。

## 5. 端到端流程与代码地图

三个质量模块之外，这里是完整的阶段序列（`AgentLoop.run()`，写死的顺序）和代码归属，方便定位问题：

```text
[1]  记任务快照        → cache/task_request.json
[2]  定检索策略（§2.1） → cache/search_strategy.json
[3]  写知识构建请求     → requests/knowledge_build_request.json
     └─ --prepare-only 到此为止（只产 A 自己的东西）
[4]  知识管线 P1–P6（§2.2–2.3）→ 8 类产物 + knowledge_bundle
[5]  白名单预锁（§2.3）→ cache/citation_ready_set.json
[6]  写综述生成请求
[7]  写初稿（§3.1）    → output/survey.md
[8]  查-修循环（§3.2–3.4）：verify ⇄ Goal Gate ⇄ revise
[9]  评分 + 渲染（§4.1）→ HTML/PDF + 质量报告
[10] 最终状态          → completed | quality_failed
```

代码住哪：`harness/` = 调度（agent_loop / planner / tool_registry / goal_gate / agents/）；`tools/` = 干活（phases/ 知识管线、write/verify/revise/render 四件套、clients/ 外部服务封装、models/ 数据格式、verify/ & nlp/ 校验工具）。工具由 `tool_registry.py` 进程内调用，带超时和结果截断；工具失败直接 raise（fail-fast，不静默吞）。

## 6. 目录与数据流

```text
requests/   流程上下文的请求文件（上一步给下一步递话）
cache/      中间产物：知识包、8 类知识产物、白名单、claim 地图……（对账都在这）
output/     交付物：survey.md、final_report.html/pdf、质量报告、修复日志、最终状态
logs/       run.jsonl（全过程事件流）+ state.json（流程推进到哪步了）
memory/     策略记忆（跨运行保留）
```

8 类知识产物是所有环节的共享词汇表：论文列表、解析全文、图库、表库、论文卡片、证据库、分类、引用索引（schema 都在 `tools/models/`）。

## 7. 反幻觉链（enforced，改动不得破坏）

五道锁，每道都是代码强制：

1. 论文的标题/作者/年份只能来自 SciVerse API 的返回，LLM 生成的一律不算。（检索侧）
2. 每个论断必须绑定到具体证据（claim map，`tools/verify/claim_mapper.py`），证据带页码和文档 id，能溯源。（检索→验证）
3. 每条引用过白名单 + 语义校验。（验证侧）
4. 归属检查：别人的工作不能说成引用论文自己的。（验证侧）
5. 图表只能来自解析论文挖出的图库/表库，或由已验证内容生成的可视化。（检索→写作）

## 8. 常用开关速查

| 开关 | 默认 | 作用 |
|---|---|---|
| `--mode demo / full` | demo | full 启用 LLM 策略构建 + 策略 Agent |
| `--prepare-only` | 关 | 只产请求文件，不跑 B/C |
| `--use-mineru` | 关 | 开 PDF 解析 |
| `EVISURVEY_REAL_NLI` | 关 | 真语义校验模型（修复实验必须开，同时配 `HF_HUB_OFFLINE=1`） |
| `EVISURVEY_REPAIR_AGENT` | 关 | 修复 Agent（动作式修复） |
| `EVISURVEY_JEV` | auto | 修复 Agent 的动作选择走 JEV 分类（auto=有 `TYPESAFE_API_KEY` 即启用；off=全走 Intern-S2；on=必须有 key 否则报错） |
| `EVISURVEY_AGENT_TOOLS` | 关 | 关节用原生 tool calling 对话格式（默认 JSON 格式） |
| `EVISURVEY_COVERAGE_MIN` | 0.7 | 覆盖闸阈值 |
| `EVISURVEY_WRITER_LLM` | 关 | 正文走 LLM（关 = 纯模板） |
| `FINAL_SEED_PAPERS` | 关 | 加载预置种子数据（演示复现，数据是真实跑出来的） |

## 9. 踩过的坑（改代码前必读）

- 真语义校验的运行必须同时设 `HF_HUB_OFFLINE=1`，否则一个到 HuggingFace 的连接探测失败会让整个运行崩掉。
- **跑全量单测前先归档真跑产物**——历史上测试套件会覆盖 live 的 cache 文件，吃过大亏（已修，但归档习惯保留）。
- 16GB 内存机器上，full 模式 + 修复 Agent 可能在最后校验时被系统静默杀掉（没有报错栈），用 `--max-papers` 减负。
- Intern 默认先思考再回答，输出预算小时答案会被思考挤没——这是生成任务路由给 DeepSeek Flash 的原因。
- `output/` 会积累多个运行的文件，事后评测必须配对**同一次运行**的证据库。
- NLI 评测遵循模型给的**标签**而非置信度分数（置信度区间压缩，同文本 ≈0.56 反而低于 0.6 阈值）。

更多运行/评测陷阱见 `docs/运行与测试.md`。
