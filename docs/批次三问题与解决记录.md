# 批次三问题与解决记录（2026-09-08）

批次三目标：canonical 地标进语料（T6 标题检索+硬保留、T7 aspect 骨架）。三轮 E2E 迭代中发现并解决的问题、以及确诊但未解决的问题，全部记录在此，供后续批次直接取用。背景与验收数字见 `PROGRESS.md` 2026-09-08 Log；根因探测过程见本文。

## 已解决的问题

### 1. 标题查询"断粮"——种子引用没有标题

- 现象：T6 代码已支持标题优先查询，但首轮 E2E 的 23 个 expansion 查询全部还是 `别名+年份` 风格（如 `muzero 2020`），SciVerse 返回无关论文。
- 根因：`cache/surveys.json` 的 `meta_data.top_referenced_papers` 是裸 hint 字符串（`world_models_2018`），`_reference_entry` 走 legacy 路径 `title=""`，标题查询永远不触发。
- 解决（`e22f8cc`）：17 个 hint 升级为 `{"paper_id_hint","title","year"}` 结构条目。标题来源只取两类：`cache/canonical_papers.json` 的精确标题 + 确定无疑的著名论文（DQN/AlphaGo/AlphaZero/Voyager/AgentBench）。**不确定的一律不猜**——猜错标题会被规范化相等匹配拉回错误论文。
- 效果：canonical 入语料 5 → 10。

### 2. seed_survey_bibs.json 标题污染——不可接入生成侧

- 现象：原计划把评测期建的 `cache/seed_survey_bibs.json`（7 篇综述真实 bib 并集，13/23 带标题）作为带标题候选接入。逐条检查发现自动解析有实错：`cradle_2024` → "Cradle-to-cradle business model tool"（商科论文，完全错误）；`sora_2024` → "Open-Sora: Democratizing..."（开源复现，非所指对象）。
- 决定：**否决直接接入**。错误标题 + 标题精确匹配 = 检索回错误论文，比缺失更有害。
- 遗留修法（未做）：对 seed_bib 条目做 SciVerse 验证式解析——用标题查询取 top 命中、规范化标题比对、不一致即丢弃——只让通过验证的条目进入候选。

### 3. 白名单 recency 主导仍在切地标

- 现象：地标进了语料（硬保留生效），但 `citation_prelock` 的 recency×influence 混合排序在 15 篇窗口下仍把老地标挤出（whitelist_cut 一度 7 篇）。
- 解决（`e0d81e1`）：cap 收紧时给 bib 来源（`survey_ref_count>0`）设保留通道，按 survey_ref_count 降序最多 pin 半个窗口；cap 不收紧时保持旧顺序（小池兼容）。
- 效果：whitelist_cut 7 → 6，cited 3 → 4。

### 4. 断网下系统行为正确（验证，非修复）

一轮 E2E 中途机器断网（`[Errno 8] nodename nor servname`，Intern/SciVerse DNS 全挂）：修复批决策失败记 unresolved → `revise_survey` 挂满 `TOOL_TIMEOUT_SECONDS=900` → RuntimeError 冒泡退出。fail-fast 符合设计；真跑前确认网络、日志中 Errno 8 立即判环境问题。

### 5. coverage 闸首次真实触发（验证，非修复）

终验轮 `stop_reason=coverage_fail`：修复轮把 figure_ref_retention 压到 0.667（<0.7 红线），关节3 拦停并回滚最优文本。这是该闸上线以来第一次在真实运行中触发，行为正确。后续注意：修复动作若删除图表引用句会直接撞线。

## 确诊但未解决的问题（按优先级）

### P1. canonical 仍有 10 篇 search_miss（目标 ≥12/20 未达，差 2）

构成与修法：

1. **不在种子引用清单里的地标**（PlaNet、DreamerV2、MBPO、NGU、Agent57、VPT、Cosmos 等）：种子综述的 `top_referenced_papers` 每篇只有 3-5 条人工精选，覆盖不了。诚实修法：从真实综述完整 bib 提取候选（`cache/gold_refs.json` 有 338 条真实提取，25 条 malformed 需过滤）+ 上文第 2 条的验证式解析。**禁止**直接注入 `canonical_papers.json` 评测清单——那会让 canonical hit 指标自证成立（循环作弊）。
2. **不确定标题的 hint**（sora/oasis/gtbench/avalonbench/hunyuan 等）：等验证式解析通道就绪后一并处理。

### P2. whitelist_cut 残留 6 篇

pin 只保护 `survey_ref_count>0` 的论文；经普通 aspect 检索入语料的地标（survey_ref_count=0）不受益。修法方向：把"canonical-like"信号贯通到白名单（如 P2 bib 命中的论文在 P3 命中时也打 survey_ref_count），或白名单排序的影响力信号里加引用数分位数。

### P3. grounding 跨 run 波动（0.279 → 0.173）

协议层已统一（T4/T5），波动来自内容层：GLM 转述与证据的实际支持度。26 条 claim 0 supported / 9 weak / 17 unsupported。正解是批次四（全文证据深度 + 证据分层约束写作）——writer 只有摘要时写不出方法细节句，unsupported 自然下降。

### P4. GLM 空回复（5 次/轮，归批次五 T11）

已知病灶（常思考模型吃满 token），已有 effort=low + 6000 预算 + 回退。系统性修法在 T11：输出 schema 约束、空回复统计进报告、必要时换非思考模型做段落生成。

## SciVerse 全文能力探测结论（批次四前置调研）

- `GET /content?doc_id=` **不可用**：返回 `{"code":12633,"CONTENT_NOT_FOUND","原文不存在"}`（多文档探测均如此）。
- `agentic-search` 的 `chunk` 字段是**全文切块**：带 `page_no`、`offset`、`model_name=MinerU/2.5`——SciVerse 后端本身用 MinerU 解析全文，可按语义查询定向抽取段落（修复 Agent 的 backfill 已在利用）。单 chunk 实测约 700-800 字符。
- `meta-search` 返回 `access_oa_url`（论文直链 PDF，如 `https://arxiv.org/pdf/1803.10122`）与 `access_is_oa`/`access_oa_status`。
- **结论**：SciVerse 拿不到结构化全文 → **MinerU v4 是全文主通道**（输入用 `access_oa_url` 直链），agentic chunk 做定向补充，图表从 MinerU zip 的 `content_list.json` 顺路提取。
