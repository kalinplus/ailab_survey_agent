# 相关工作对比：SurveyX / LiRA / SurGE（代码级分析）

日期：2026-08-25。范围：`ref/` 三个参考仓库的代码级分析，用于支撑报告/答辩中「背景与问题 → 引出 EviSurvey」的叙事。

与 `docs/参考 baseline.md` 的分工：那份是领域级文献调研（AutoSurvey/SurveyForge/FIKSurvey 等，来自公开论文）；本文是对本地三个仓库**逐文件核实**的代码级对比，所有结论附文件路径证据，被追问时可直接翻代码。

---

## 一、三仓库定位（先澄清身份）

| 仓库 | 出处 | 范式 | 角色 |
|---|---|---|---|
| `ref/SurveyX` | arXiv:2502.14776（IAAR-Shanghai） | 端到端流水线：关键词扩展 → 迭代召回 → 过滤 → 属性树抽取 → 大纲 → 逐节写作 → RAG 补引用 → LaTeX 图表 | 生成系统（开源版为离线阉割版） |
| `ref/LiRA` | IAAI 2026（Elsevier Research） | 多智能体反思循环：researcher → writer → reviewer → editor，各环最多 3 轮修订 | 生成系统（输入为**预定义引用池**，非开放检索） |
| `ref/SurGE` | SIGIR 2026 | 108 万 arXiv 摘要库 + 205 篇金标综述 + 覆盖/结构/内容/引用相关性四维指标 | **评测基准，不是生成系统** |

**关键澄清**：SurGE 仓库内不存在任何从 topic 到综述的生成代码（`src/` 仅 7 个评估/下载文件）。它的正确用法是「行业已量化该问题的证据来源」，不是被攻击对象。

## 二、各方法要点与代码证据

### 2.1 SurveyX

流水线（`tasks/offline_run.py` / `tasks/full_run.py`，阶段名来自 TokenMonitor 打点）：recall paper → filter paper → clean paper → generate outline → generate content → Rag refine → section rewrite → generate table → post refine → compile latex。

- **检索**：Google Scholar 爬虫队列 + 自建 arXiv 镜像（标题/摘要子串匹配），但开源配置 URL 全为空串（`config.py:29-30`）——开源版在线检索不可用。迭代召回（`paper_recaller.py:291-339`）：title+abstract 嵌入 → KMeans → 每簇 LLM 生成新关键词，迭代 ≤3 轮、池上限 1024。
- **证据粒度**：写作输入是 LLM 预抽取的「属性树」（`attri_tree_for_*.md`，有损中间表示、无溯源），全文截断 2 万 token；引用检索索引只有 title+abstract（`rag_refiner.py:113-120`）。
- **引用处理（核心攻击点）**：写作 prompt 只要求 "utilize all the paper information" 并直接输出 `\cite{}`；RAG 补引用 = 随机采样 30% 无引用句子 + 摘要级 embedding top-k + **每段引用条数 `random.randint(2, 30)`**（`rag_refiner.py:52-55, 133-147`），再机械拼接 `\cite{...}`。唯一「校验」是字符串级：非法引用键删除（`content_generator.py:418-423`）、rapidfuzz 把未知键**模糊改绑到另一篇论文**（`map_cited_bib_names_to_refs.py:34-51`）。
- **质量门**：唯一门槛是总词数 < 10000（`post_refiner.py:181-189`）；论文宣称的 outline 评分模块 `score_outlines.md` 在代码中**无任何引用（未接线）**。
- **NLI 位置**：只在离线评测脚本 `eval/eval_citation.py`（gpt-4o-mini 二值 NLI），生成闭环零验证。
- **图表**：全 LLM+模板生成（TikZ 树图、summary/comparison 表），内容来自**已生成的综述文本**而非源论文数据——可能复述正文幻觉；从原论文检索图片的功能在主管线被注释禁用（`post_refiner.py:168`）。
- **免责**：PDF 内硬编码免责声明「cannot guarantee full compliance with academic standards」（`latex_text_builder.py:66-71`）。

### 2.2 LiRA

LangGraph StateGraph（`src/builder.py`）：setup_state → analyze_all_papers（并行逐篇分析，超 1 万 token 切段）→ 分组 draft_outline → review_content(outline) → 逐节 write_content（FAISS+MiniLM 分析级 RAG）→ review_content(draft) → edit_content → 正则后处理 → 评测。

- **输入设定**：参考文献来自 SciReviewGen 金标书目（「给定引用池重写综述」），检索默认关闭（`configs/main.yaml: use_retriever: False`）；检索模块是匿名化桩，`query_api` 文档串自认 "does not work for SciReviewGen"（`src/retriever.py`）。
- **证据粒度**：默认 `fulltext: False`，即只有摘要；researcher 分析默认关闭（`researcher_model: "none"`，直接把原始摘要当分析结果传下游）。
- **引用处理（核心攻击点）**：claim-citation 匹配完全靠 LLM 自觉，prompt 的唯一约束是「引用时标题拼写必须完全一致」（为后处理正则可匹配，`src/prompts/write.py:181`）；reviewer 评审标准只查引用**格式**不查支撑（`src/prompts/review.py:71`）；**幻觉引用的归宿是被正则替换成 `[REDACTED]` 留在成稿里**（`src/utils/post_processing.py`）。
- **修复循环（注意精确表述）**：有 3 轮反思循环，但判据是正则解析的 `## SUFFICIENT`（组织性/结构/连贯类标准，`src/reviewer.py`），**无事实性门槛**；且编辑后的评审环节被 `goto=END,  # Temporary` 注释禁用（`builder.py:602-604`），编辑实际单遍。
- **NLI 位置**：只在评测侧 `utils/eval_metrics/citation_quality.py`（改编自 AutoSurvey，gpt-4o-mini 二值 NLI，证据源为摘要）。注意：仓库内附带的 AutoSurvey 基线反而有回路内 LLM 引文自检（`autosurvey/src/agents/writer.py:334-356`），LiRA 主方法没有。
- **图表**：完全没有（全库无图片/表格生成代码，输出纯文本转 CSV）。

### 2.3 SurGE（基准）

评估流水线（`src/evaluator.py` 等）：markdown 解析 → 引用标题规范化匹配（仅保留 `[a-zA-Z]` 小写精确匹配）→ ROUGE/BLEU → SH-Recall（嵌入软标题召回）→ Structure_Quality（GPT-4o 0-5）→ Coverage（金标引用召回）→ Relevance Paper/Section/Sentence（deberta-v3 NLI）→ Logic（GPT-4o 抽样 ≤20 段、每段截断 1000 字符）。

- **语料只有元数据+摘要**（无全文无 PDF）——该基准上的系统只能基于摘要写作。
- **句子级 NLI 测的是「可引性」而非「蕴含性」**，模板原文（`src/informationFuncs.py:195`）：`"The paper titled '{title}' with the given abstract could be cited in the sentence: '{sentence}'."` —— 判「该论文可以被引在这句」，不判「该句论断被该文蕴含」。
- **论文数据（引自 `docs/参考 baseline.md`，出处 arXiv:2508.15658）**：检索阶段召回上限 ~68%，端到端引用召回 < 10% —— 瓶颈不在「找不到论文」，在「检索到的证据不被使用」。
- 自带反面教材：Naive 基线参考文献 [71]-[100] 是 6 个模板标题循环重复的幻觉引用；ID 基线自曝引用是 placeholders（`baselines/ID/output/...` 第 540 行 Note 原文）。
- 评测自身弱点（顺带可提）：引用出现在金标 `all_cites` 里直接计 hit 不做 NLI（循环性，`informationFuncs.py:30-31`）；标题匹配正则连撇号都处理不了；Logic 只抽 20 段打印象分。

## 三、共性问题轴（问题 → 我们的机制）

### 问题 1：NLI 全都长在评测目录里，没有一个长在生成回路里

- SurveyX：`eval/eval_citation.py`（离线脚本）；LiRA：`utils/eval_metrics/citation_quality.py`；SurGE 整个仓库就是评测。
- 含义：作者们都知道引用忠实度是问题（否则不会写这些评测），但都止步于「事后打分」，没有一个把验证失败变成生成期约束信号。
- **EviSurvey**：把 NLI 搬进生成回路——`tools/verify/claim_mapper.py` 绑定 claim→evidence，`tools/nlp/nli_verifier.py` 逐条验证，失败直接驱动修复（问题 2）。

### 问题 2：修复循环的门槛是「风格/字数」，不是「证据」

- SurveyX 唯一质量门 = 总词数 < 10000；宣称的 outline 评分模块未接线。LiRA 循环判据 = SUFFICIENT 正则（结构/风格），无事实门槛，编辑后评审被禁用。
- **EviSurvey**：确定性 Goal Gate（`harness/goal_gate.py`）三道闸——invalid 引用 = 0；unsupported claim 清零或预算尽；coverage 保留率 ≥ `EVISURVEY_COVERAGE_MIN`（默认 0.7，以 round 0 为基线，拦「删光了就达标」的取巧）——外加不动点检测 + best-so-far 回滚。修复 Agent（`harness/agents/repair_agent.py`）按 A–E 失败分组选动作（remap/rewrite/swap/backfill/delete-最后手段），改写句**增量重过 NLI**。关键差异：**触发条件是验证失败，不是字数或风格印象**。

### 问题 3：引用是「装饰性」的——随机条数 + 摘要相似度 + 机械拼接；幻觉靠涂黑/免责

- SurveyX：`random.randint(2,30)` 条引用机械拼接；模糊改绑。LiRA：`[REDACTED]` 留在成稿。SurveyX：PDF 硬编码免责声明。
- **EviSurvey**：元数据只来自 SciVerse API；引用必须存在于 `citation_index` 白名单；A 类失败一次 remap 修全部出现；删是最后手段且有 coverage gate 兜底。

### 问题 4：证据粒度停留在摘要级/有损中间表示；图表缺失或反推自生成文本

- SurGE 语料 abstract-only；LiRA 默认 `fulltext: False` 且检索桩不可用；SurveyX 属性树（有损、无溯源）+ 引用索引 title+abstract。图表：LiRA/SurGE 为 0；SurveyX 从生成文本反推。
- **EviSurvey**：SciVerse agentic-search 分块证据 + 可选 MinerU 全文解析（`--use-mineru`）；`evidence_store` 保留 chunk 级证据；`figure_bank`/`table_bank` 从已验证论文**挖**原图原表；生成式视觉只从 verified content 派生。

### 问题 5（文献调研侧）：检索质量无人负责

- LiRA 不检索（金标引用池）；SurveyX 开源版检索不可用、关键词扩展 LLM 一遍过；SurGE 论文量化了断层（68% vs <10%）。
- **EviSurvey**：关节1 策略 Agent（`harness/agents/strategy_agent.py`）——probe→cluster→naming→sample→edit-loop(≤3) 的**有界**循环 + 确定性闸门 + best-so-far 回滚 + trajectory jsonl，每 aspect 真实 meta-search。对比 LiRA 的反思循环：有预算断路器和可审计轨迹，"agentic but bounded"。A/B 对照见 `scripts/run_strategy_ab_test.py`、`scripts/run_repair_ab_test.py`。

### 问题 6（次要）：评测自证清白

- SurGE 论文自己指出早期方法「自证清白」型评测的系统性偏差。
- **EviSurvey**：三层事后评测（NLI 引用质量 / gold 参考覆盖 / Intern-S2 judge + 修复关节 A/B 表，`scripts/run_survey_eval.py`），且明确处理了评测自身陷阱（产物跨 run 不一致、NLI margin 压缩→按 label 判、证据切句窗、跨语言 neutral 偏差，见 CLAUDE.md Known traps）。

## 四、问题 → 机制映射表（可直接放报告）

| 已有方法的缺口 | EviSurvey 对应机制 |
|---|---|
| NLI 只在评测侧，生成期零验证 | Claim-to-Evidence Map + 生成期逐 claim NLI（verify_citations） |
| 质量门是字数/风格，无证据门槛 | Goal Gate 三道闸（invalid=0 / unsupported 清零 / coverage≥0.7）+ 不动点 + best-so-far 回滚 |
| 幻觉引用靠涂黑/免责/模糊改绑 | citation_index 白名单 + 失败分组修复（remap 一次修全部出现）+ 删是最后手段 |
| 证据=摘要/有损属性树，无 span 级 grounding | agentic-search 分块证据 + MinerU 全文 + evidence_store |
| 无图表，或图表反推自生成文本 | figure_bank/table_bank 从已验证论文挖掘 |
| 检索策略一遍过、无人负责 | 有界策略 Agent（关节1），A/B 对照验证 |
| 评测自证清白 | 三层事后评测 + 关节 A/B 报告 + 评测陷阱的显式处理 |

## 五、叙事骨架（背景与问题 → 引出方法，可直接改写）

> **背景**：自动综述生成已经从两阶段 RAG（AutoSurvey）演进到多智能体（LiRA）与端到端系统（SurveyX），评测也趋于标准化（SurGE 四维框架）。
>
> **问题一（核心断层）**：SurGE 的诊断显示，检索召回上限约 68%，而端到端引用召回不足 10%——「检索到论文」和「论断被证据支撑」是两件事。但考察现有开源实现会发现：引用忠实度的 NLI 检查无一例外长在评测目录里（SurveyX `eval/`、LiRA `utils/eval_metrics/`），生成回路里引用选择仍靠 LLM 自觉 + 摘要级相似度，甚至随机注入（SurveyX 每段引用数 `random.randint(2,30)`）。
>
> **问题二（修复缺失）**：现有系统的「质量门」是字数（SurveyX）或风格评审（LiRA 的 SUFFICIENT），没有证据门槛；幻觉引用的归宿是 `[REDACTED]`、免责声明或模糊改绑，而非被修复。
>
> **问题三（证据与呈现贫乏）**：证据粒度停留在摘要或有损中间表示，无原文级 grounding；图表缺失或反推自生成文本本身。
>
> **引出 EviSurvey**：我们把「评测侧的验证」内化为「生成时的约束」——每条论断绑定 chunk 级证据、每条引用过 NLI 与白名单、验证失败驱动有界修复（三道闸 + best-so-far 回滚），图表从已验证论文挖掘；检索策略与修复行为均由有界 Agent 承担并可审计。

## 六、答辩注意事项（精确性陷阱）

1. **别攻击 SurGE 的「生成质量」**——它是基准。正确用法：引其论文数据（68% vs <10%）+ 指出其 NLI 指标测「可引性」而非「蕴含性」（`informationFuncs.py:195` 的 "could be cited" 模板原文值得直接引用），说明「行业已知问题、但现有系统未解决」。
2. **说 LiRA「没有修复循环」是错的**——它有 3 轮反思循环。精确说法：「循环判据是结构/风格，无事实性门槛，且编辑后评审被禁用（`goto=END # Temporary`）」。
3. **LiRA 仓库里的 AutoSurvey 基线反而有回路内引文自检**——对比时精确到「LiRA 主方法」，避免被反杀。
4. **主动承认取舍**：write_survey 是模板化起草（可解释、可验证）vs SurveyX/LiRA 的自由 LLM 写作（行文更流畅但不可控）——为验证性付出的代价，先说破比被问破好。
5. SurGE 论文数据（68% / <10%）出自 arXiv:2508.15658，别引成仓库内容；仓库里能引的是 NLI 模板原文与 baseline 幻觉引用实例。
