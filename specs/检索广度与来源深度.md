# S1 检索广度与来源深度

Status: dispatching (2026-09-03)

## Motivation

评测 v2 首跑：语料仅 12 篇 / 5 类，gold（338 篇）参考召回 0.033；
evidence store 48 条全部摘要级（MinerU 默认 off）。检索广度与来源深度
双不足 → L2' coverage 虽 1.0 但论文池太窄，writer 可选证据天然贫乏。
（L2' citation depth 0.0 / corpus utilization 0.0 是 id 失配告警，由 S0
交付重跑解决，不在本 spec 范围。）

## Boundary（触达文件）

- `tools/phases/phase3_paper_retriever.py`（广度：每 aspect 子查询数、top_k、
  跨 aspect 去重保广度、relevance 过滤阈值）
- `tools/phases/phase5_evidence.py`（深度：核心论文 MinerU 全文进 evidence store）
- `harness/search_strategy_builder.py`（如需 breadth 旋钮，优先 env/STRATEGY_* 配置，
  不新增复杂逻辑）
- 对应单测（`tests/unit/test_phase3.py` / `test_phase5_evidence.py` /
  `test_search_strategy_builder.py`，编辑既有文件）
- **不碰**：`tools/write_survey.py`、`harness/agents/`（strategy_agent 已在工作，
  除非 breadth 旋钮必须经它传递）、`tools/verify_*`、`PROGRESS.md`、`specs/`。

## Interface Contract

- 各 phase 对外函数签名与 bundle schema（`cache/knowledge_bundle.json` 8 artifacts）
  不变；广度旋钮经 env / config 传入，默认值保证 demo 模式行为不回归。
- MinerU 全文仅对 P3 选出的核心论文开启（复用既有 `use_mineru` 路径，
  默认仍 off；`--use-mineru` 打开时核心论文走全文、其余摘要，
  失败降级 abstract_only 照旧——这是既有边界降级，不新写 fallback）。
- 广度上限：新增 `EVISURVEY_MAX_CORPUS`（默认维持现状数值），超出时按
  aspect 均衡裁剪而非全局 top 裁剪（防单类目淹没）。

## Slices

1. 广度：per-aspect 查询数 / top_k / relevance 阈值旋钮化 + 跨 aspect 去重保广度。
2. 深度：核心论文 MinerU 全文进 evidence store（abstract + fulltext 双层）。
3. （仅当 S2 需要）citation_ready_set / taxonomy 输出不缩水：类目数与每类论文数
   下限保护。

## Acceptance Criteria（unit，fake API，无网络）

1. 广度旋钮打开时，fake meta-search 返回的候选经 dedup + 过滤后语料规模
   显著大于默认（断言单调性 + `EVISURVEY_MAX_CORPUS` 上限生效且裁剪后
   每 aspect 论文数 ≥ 1）。
2. relevance 过滤不破坏覆盖：构造 5 aspect 候选集，断言每 aspect 至少
   存活 2 篇（当前实现若做不到则以旋钮实现之）。
3. demo 模式默认值下各 phase 输出与当前实现兼容（既有测试全绿）。
4. `pytest tests/unit/` 全绿。

## Real-API Acceptance（S0，主会话合并后做，不在本 worktree）

真跑 full：语料 12 → ≥30 篇且 5 类目全覆盖；gold reference recall ≥ 0.10；
L2' coverage 维持 1.0。
